The published v2.6.7 installer at commit `047ce167685f6de8db86519557b865e9f23e98f3` accepts only numeric `major.minor.patch` remote installer versions; `v2.7.0-rc.1` fails that parser and blocks its automatic component update. Keep candidates on explicitly selected feature refs or verified commits. Release consistency rejects an RC for a GitHub pull request targeting `master`, a push or merge queue for `master`, or a local checkout of `master`.

## Choose source and binary channel separately

`--installer-branch` selects the installer repository ref and its matching installer/service/helper bundle. Supported refs include safe branch names, published tags and full commit SHAs. Prefer the exact reviewed commit for reproducible candidate testing; a branch can change between downloads. Do not assume a version printed by the installer pins its source. An explicit ref takes precedence over saved `INSTALLER_BRANCH`, then the reported default `master`.

The separate `--adguardhome-branch` accepts `release`, `beta` or `edge`. Archive metadata calls the `release` channel `stable`. The older `--branch` option is an AGH-channel alias, not an installer ref. Omit an AGH channel override when preserving the installed channel is intended. An installer RC does not require the AGH beta or edge channel.

## Fetch and verify before running

Use SSH on supported test hardware, with Entware mounted before installation. Keep the router-stock PATH first. These commands use router-stock `/usr/sbin/curl`; SHA-256 uses a functional PATH provider or router-stock `/usr/sbin/openssl`. They do not require a new Entware package. The block pins the qualified implementation and expected installer hash; verify both against the candidate record before execution. Do not execute a partial or unverified download. Validation and download run in a subshell so a failure leaves the SSH session open. After reserving its private directory, the block removes that directory on failure or interruption; successful preflight retains it for the following action. Each transfer has a ten-second connection limit and sixty-second total limit, with at most two retries. Continue only if the entire block succeeds and enters the candidate directory.

```sh
export LC_ALL=C
export PATH="/sbin:/bin:/usr/sbin:/usr/bin${PATH:+:$PATH}"
INSTALLER_REF='733bc9568725c9b866dedce71ec535d2f3b8e8e6'
EXPECTED_INSTALLER_SHA256='da021378d9e9a7283fef5b1766dbf811bfb749b0dd78437cf5d63868abe978fa'
CANDIDATE_DIR="/tmp/agh-v270-candidate.$$"
(
  case "${INSTALLER_REF}" in
    '' | *[!0-9a-f]*) printf '%s\n' 'Replace INSTALLER_REF with the verified full candidate commit SHA.' >&2; exit 1 ;;
  esac
  [ "${#INSTALLER_REF}" -eq 40 ] || exit 1
  case "${EXPECTED_INSTALLER_SHA256}" in
    '' | *[!0-9a-f]*) printf '%s\n' 'Replace EXPECTED_INSTALLER_SHA256 with the expected candidate SHA-256.' >&2; exit 1 ;;
  esac
  [ "${#EXPECTED_INSTALLER_SHA256}" -eq 64 ] || exit 1
  (umask 077 && mkdir "${CANDIDATE_DIR}") || exit 1
  trap 'rm -rf "${CANDIDATE_DIR}"' 0
  trap 'exit 1' HUP INT TERM
  /usr/sbin/curl -fL --connect-timeout 10 --max-time 60 --retry 2 -o "${CANDIDATE_DIR}/installer" \
    "https://raw.githubusercontent.com/jumpsmm7/Asuswrt-Merlin-AdGuardHome-Installer/${INSTALLER_REF}/installer" || exit 1
  if HASH_OUTPUT="$(sha256sum "${CANDIDATE_DIR}/installer" 2>/dev/null)"; then
    ACTUAL_INSTALLER_SHA256="$(printf '%s\n' "${HASH_OUTPUT}" | awk '{ print $1; exit }')"
  elif HASH_OUTPUT="$(/usr/sbin/openssl dgst -sha256 "${CANDIDATE_DIR}/installer" 2>/dev/null)"; then
    ACTUAL_INSTALLER_SHA256="$(printf '%s\n' "${HASH_OUTPUT}" | awk '{ print $NF; exit }')"
  else
    printf '%s\n' 'No functional SHA-256 provider; installer was not run.' >&2
    exit 1
  fi
  [ "${ACTUAL_INSTALLER_SHA256}" = "${EXPECTED_INSTALLER_SHA256}" ] || {
    printf '%s\n' 'Installer SHA-256 mismatch; installer was not run.' >&2
    exit 1
  }
  cd "${CANDIDATE_DIR}" || exit 1
  sh installer preflight || exit 1
  trap - 0 HUP INT TERM
) && cd "${CANDIDATE_DIR}"
```

Use the same verified `INSTALLER_REF` in the action below so helper downloads come from the matching source. Retain the source and hash in the run record. Download failure or hash mismatch is a stop condition; do not fall back to master or bypass verification. The installer independently verifies managed artifacts during the selected action.

For an existing v2.6.7 installation, bootstrap candidate testing by downloading and verifying this candidate installer first, then invoke that verified file with the explicit candidate ref as shown below. The installed v2.6.7 installer's automatic update cannot parse the RC version; selecting the candidate only through that old updater is insufficient.

## Fresh installation and existing-environment updates

Fresh setup is interactive and still requires timezone, credentials and DNS/cache choices. After preflight, use the positional ref with the interactive install action:

```sh
sh installer "${INSTALLER_REF}" install
```

`sh installer install --yes` does not supply first-run configuration. Flagged non-interactive install requires an existing configured environment; a passing preflight does not change that contract. Prior interrupted-transaction recovery may run before a diagnostic or refused command and must be reported separately.

Before updating an installed environment, record the current installer ref/version, AGH channel/version, topology/cache, script hashes and running/stopped state. Create and preserve the validated backup in private storage outside the installation being changed. The default backup path below requires mounted Entware and an existing installation.

```sh
sh installer backup --yes
sh installer update --installer-branch "${INSTALLER_REF}" --yes --dry-run
sh installer update --installer-branch "${INSTALLER_REF}" --yes
sh installer status
sh installer doctor
```

The backup archive is normally `/opt/etc/backup_AdGuardHome.tar.gz`; confirm success and retain a separate pre-upgrade copy before proceeding. It can contain secrets and must not be attached to an issue. A dry run is a preview, not proof of actual migration or recovery. Test v2.6.7 upgrades both while running and stopped, repeated repair/update, validated restore, uninstall and meaningful interruptions using the checklist.

To deliberately select a binary channel, add its separate option to the chosen update action; for example:

```sh
sh installer update --installer-branch "${INSTALLER_REF}" --adguardhome-branch beta --yes
```

Record that channel switch explicitly. Test actual `release`, `beta` and `edge` service/DNS lifecycles separately for each claimed architecture. Executing a binary or validating its configuration does not prove restart/stop/recovery parity.

For an inspection using the installed bundle, `sh installer --no-auto-update status` opts out of automatic component updates for that invocation. Bundle-changing install/update/restore/channel actions refuse under this opt-out, including their dry runs; it cannot be combined with the examples above to obtain a binary-only update. The flag does not waive checksums or change AGH channel.

## Recovery and rollback rehearsal

Keep the previously verified source, hashes and pre-upgrade backup available before testing. Source switching alone does not reverse YAML/schema changes, binary versions, topology or DNS preferences. Direct downgrade compatibility is a qualification target; do not mark it supported without an actual matching test.

The published v2.6.7 source is recorded historically at commit `047ce167685f6de8db86519557b865e9f23e98f3`. For a rehearsal, verify the prior installer using the download/hash procedure above with the prior source and its independently recorded expected hash. A published tag may be used after verifying its resolved commit. Do not substitute an assumed `v2.7.0-rc.1` tag. Use the known-good installer to preview and restore its validated pre-upgrade backup:

```sh
LAST_GOOD_REF='047ce167685f6de8db86519557b865e9f23e98f3'
sh installer restore --installer-branch "${LAST_GOOD_REF}" \
  --file /opt/etc/backup_AdGuardHome.tar.gz --yes --dry-run
sh installer restore --installer-branch "${LAST_GOOD_REF}" \
  --file /opt/etc/backup_AdGuardHome.tar.gz --yes
sh installer status
sh installer doctor
```

Run these commands from the directory containing the verified prior installer, against the preserved pre-upgrade archive, in the controlled rehearsal. Record original and restored versions, source/channel, TCP/UDP listeners, DHCP/local DNS, shared hooks, settings and native-DNS recovery. If backup validation or restore fails, retain the reported transaction/recovery paths and use the supported recovery procedure for the actual stage; do not delete recovery journals or overwrite shared hooks wholesale. Re-run client DNS checks after recovery. Retain a console/SSH path for cases where DNS is unavailable.

## Sanitized support report

The candidate diagnostic contract is opt-in collection to an absolute local file:

```sh
sh installer support-export --output /tmp/agh-v270-support.txt
```

Covered collector/startup/privacy/path/limits and actual guest full/read-only refusal are recorded as software evidence; record a new router collection separately. The bounded allowlisted report must omit secrets, raw private configuration/NVRAM, query history and identifying client/domain/address data. Review the file locally before choosing to share it; there is no automatic upload. Record missing/full/read-only storage and unsafe-output-path results separately from any reported recovery of an older pending transaction. This report supplements exact test identity and observations; it does not certify hardware or replace private backup files.
